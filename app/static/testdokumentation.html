Befehle zur Testausführung
Lokalen Server starten (venv + Server)
cd warp-main .venv\Scripts\activate python run.py

Startet auf http://127.0.0.1:5000 (Admin: admin / warp2024, per Debug-Reloader neu geladen bei Codeänderungen). Erforderlich für: alle Frontend-/E2E-Tests (Fixture live_server startet den Server sonst selbst, wiederverwendet ihn aber, falls er schon läuft) und für die Play-Buttons in dieser Doku – die laufen laut _test_runner_enabled() nur, wenn dieser Server lokal mit debug=True aktiv ist. macOS/Linux: source .venv/bin/activate statt .venv\Scripts\activate.

Unit-Tests (kein Browser, schnell)
pytest tests/unit/ -v

Kein Browser, kein laufender Server nötig. Flask-Test-Client wird intern gestartet.

Einzelne Test-Suite (Frontend / Gherkin)
pytest tests/step_defs/test_recommendations_steps.py tests/step_defs/test_inbox_steps.py --browser chromium -v

Flask-Server auf localhost:5000 wird automatisch gestartet und am Ende gestoppt.

Alle Frontend-Tests
pytest tests/ --ignore=tests/unit --ignore=tests/e2e --browser chromium -v
E2E Live-Test (gegen Render)
pytest tests/e2e/ --browser chromium -v -s

Erfordert aktive Internetverbindung. Render kann beim Cold-Start bis zu 30 s brauchen.

Alle Tests (Unit + Frontend)
pytest tests/unit/ tests/step_defs/ --browser chromium -v

Die Frontend-Tests liegen als Gherkin-Szenarien in tests/features/*.feature vor, ausgeführt über die Schritt-Definitionen in tests/step_defs/.

Überblick über das verwendete Framework, die Fixtures und das Page Object Model.
